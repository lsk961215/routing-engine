# 9번: 회전 제한 정합성 검증

2026-09-23, `seoul-routing.osm.pbf` 기준. 원본 데이터를 수정하지 않았다.

## 구현한 검사

기존 참조 존재·멤버 형식·노드 경유 검사에 다음을 추가했다.

- from/to/via 누락을 각각 집계하고 중복 멤버와 비표준 역할을 구분한다.
- 여러 via Way를 관계에 기록된 순서대로 통과할 수 있는지 검사한다.
- 각 경유 도로에서 실제로 하나 이상의 서로 다른 노드 간 구간을 지나야 한다. 같은 교차점에서 경유 도로를 건너뛰는 경로를 허용하지 않는다.
- 먼저 방향을 무시한 연결성을 검사하고, 자동차 후보 도로에 대해서는 일방통행까지 적용해 검사한다.
- 한 도로가 여러 번 등장하는 경로와 반복 교차점의 가능성을 고려해 도달 가능한 연결 노드 집합을 다음 도로로 전달한다. 멤버 순서를 추측해 재배열하지 않는다.
- via-way 검사가 성공해도 탐색용 회전 전이 지원이 완료되지 않았으므로 보류 표시는 유지한다.

## 실제 데이터 대조

`osmium getid`로 해당 Relation과 참조 엔티티를 추출해 코드의 분류와 대조했다.

| Relation ID | 직접 확인한 내용 | 분류 |
| --- | --- | --- |
| 4207547 | via Node와 to Way만 존재하며 from 멤버 없음 | MISSING_FROM, INVALID_MEMBERS |
| 4627278 | from Way 184257578의 마지막 노드가 via 2351053082이고 oneway=-1. 이 도로에서 via로 진입할 수 없음 | DIRECTION_CONFLICT |
| 4661485 | via 3391918749가 to Way 71105478의 노드 목록에 없음 | DISCONNECTED_VIA |
| 11909875 | from Way 468202418이 현재 추출본에 없음 | MISSING_REFERENCE |
| 8107280 | from 285240589 → via 565574608 → to 565574610이 연결되고 모두 oneway=yes | 연결·방향 통과, VIA_WAY_DEFERRED |

재현 예시 (backend에서 실행):

```sh
osmium getid data/processed/seoul-routing.osm.pbf \
  r4207547 r4627278 r4661485 r11909875 r8107280 \
  -r -f osm -o /tmp/restriction-review.osm --overwrite
```

현재 추출본에서 확인한 사실이며 원본 전체 또는 현재 OSM 서버에도 같은 문제가 있다는 의미는 아니다.

## 처리 방침

아래는 다음 그래프 생성기에 적용할 정책이다. 아직 그래프 생성기가 없어 실행 차단까지 연결하지는 않았다.

| 분류 | 그래프 생성 시 방침 |
| --- | --- |
| 모든 검사 통과 노드 경유 후보 | 회전 전이로 변환 후 탐색 테스트로 검증 |
| 승용차에 명시적으로 적용되지 않는 예외 | 예외 근거를 기록하고 승용차 제한에서는 제외 |
| 누락 참조·멤버 오류·연결 불일치·방향 충돌 | 임의 보정하지 않고 검증 실패로 처리. 입력 보완 또는 개별 검토가 필요 |
| via-way·조건부·미해석 값·미지원 구조 | 지원 로직 구현 또는 명시적 정책 결정 전 운영용 그래프 생성 차단 |
| 자동차 후보 밖의 Way 참조 | 관련 전이가 실제 그래프에 존재하지 않는지 확인 전 보류. 특히 only_*를 임의로 버리지 않음 |

기본 정책은 **미해결 제한이 남으면 운영용 그래프 생성을 중단**하는 것이다.
문제 데이터를 조용히 제외한 그래프를 정상 차량 경로용으로 취급하지 않는다.
분석 명령 자체는 진단을 위한 것이므로 문제를 보고해도 실행 성공으로 끝난다.

## 검증과 남은 범위

백엔드 테스트 총 21개 통과. 이번에 복수 via-way, 역방향, 끊어진 연쇄,
경유 도로 건너뛰기, 닫힌 경유 도로, 누락 역할과 중복 멤버 회귀 검증을 추가했다.

정합성 검증은 완료했지만 데이터 오류를 모두 수정한 것은 아니다.
지리적 회전 각도, 분할된 도로의 실제 전이 생성, 시간 조건 해석, 그래프 차단 정책 연결은 후속 작업이다.
다음은 이 검증 결과를 반영한 노드·간선·회전 전이 및 가공 파일 구조 설계다.

## 서울 추출로 인한 누락 여부: 전국 원본 대조

로컬 전국 원본 `raw/south-korea-260919.osm.pbf`(287,579,345 bytes)와
서울 추출본(44,111,587 bytes)을 비교했다. 서울의 회전 제한 6,393개 ID를 뽑은 다음,
각 파일에서 동일 ID와 참조 엔티티를 `osmium getid --add-referenced`로 수집했다.

- 6,393개 Relation 모두 양쪽에 있고 버전·타임스탬프·태그·멤버 순서와 역할이 동일하다.
- 서울에 포함된 참조 Way 5,399개의 버전·태그·노드 참조 목록도 전국 원본과 동일하다.
- from 415개, to 417개, via 223개의 멤버 자체 누락은 전국 원본에서도 동일하다.
- 대상 엔티티 누락 3건은 전국 원본에 존재한다. 이 3건은 서울 추출 때문에 발생했다.

| Relation | 서울에 없는 from Way | 전국 원본 |
| --- | --- | --- |
| 11909875 | 468202418 | 존재 |
| 11909876 | 468202416 | 존재 |
| 20284545 | 1460674135 | 존재 |

전국 원본에서 수집한 동일한 6,393개 제한과 참조 엔티티에 기존 Java 검증기를 실행했다.
참조 누락이 3→0, 노드 경유 후보가 4,964→4,967로 바뀌었다.
멤버 구조 불일치 744, 연결 불일치 72, 방향 충돌 343과 나머지 사유는 모두 그대로였다.
따라서 이 입력에서 추출에 의한 참조 누락 3건을 복구해도 다른 검증 문제는 해결되지 않는다.

전국 원본 역시 대한민국 지역 추출본이므로, 멤버 자체 누락 등이 전 세계 OSM 원본에도
존재한다고 단정하지 않는다. 이번 비교가 확인한 범위는 로컬 전국 원본과 서울 추출본 사이의 차이다.
원본이나 서울 데이터 파일은 변경하지 않았다.

후속 조치: 서울 그래프를 만들 때 대상 회전 제한의 참조 도로와 노드를 전국 원본에서
보충하는 단계를 둔다. 멤버 자체 누락·연결 불일치·방향 충돌은 별도 정책으로 처리해야 한다.
