# 좌표 탐색 복사 제거 및 로컬 성능 측정

## 변경 내용

이전 `CoordinateRouter`는 매 요청마다 모든 노드·간선을 순회하고, 출발·도착 간선을 분할한
새 RoutingGraph를 생성했다. 좌표·간선 배열 복사, 전체 정렬, 전체 회전 제한 재생성,
노드 ID HashSet 검증도 요청마다 반복됐다.

현재 구현은 원본 그래프와 공간 인덱스, 구간별 방향성 간선 목록을 공유한다.
출발 구간은 남은 거리로 Dijkstra의 초기 상태를 만들고, 도착 구간은 진입이 허용될 때
부분 거리로 목적지 후보를 평가한다. 원본 회전 제한을 그대로 조회한다.

- 공유 그래프의 노드·간선·제한을 복사하거나 변경하지 않는다.
- 내부 지점에서 도로 방향을 임의로 바꾸는 가상 교차점도 만들지 않는다.
- 동일 구간에서 정방향으로 도착 가능하면 직접 부분 거리 후보를 만든다.
- 역방향 목적지는 기존 도로망에 합법적인 우회가 있을 때만 도달한다.
- 정확한 교차점에서 시작하면 진입 간선 없이 나갈 수 있는 원래 출발 의미를 유지한다.
- 탐색 중에는 진입 간선별 best(double)·previous(int) 배열, 우선순위 큐와 경로 결과만 생성한다.
  배열 본체는 간선 수 E에 대해 약 12E bytes이며, 큐·결과·스냅 후보 등은 추가다.

아직 배열의 할당·초기화는 O(E)다. 이번 작업은 전체 그래프 복사를 없앤 것이며,
탐색 공간을 방문한 간선 수만큼만 할당하거나 메모리 풀을 도입한 것은 아니다.

## 검증

- 이전 복사 구현을 `LegacyCoordinateRouter`라는 **테스트 전용** 기준 구현으로 고정했다.
- 일방통행·회전 제한을 포함한 합성 격자에서 고정 시드 250개 좌표 쌍의 도달 가능 여부와
  최단 거리를 비교했다. 모든 결과가 일치했다 (거리 허용 오차 1e-7m).
- 역방향 지점에 도달하려면 한 바퀴 우회해야 하는 일방통행 고리와 해당 회전이 금지된 경우,
  0비용 순환도 추가 검증했다.
- 백엔드 테스트 45개 통과. 테스트용 기준 구현과 벤치마크는 운영 JAR에 포함되지 않는다.
- 최적화된 서버로 브라우저 경로 표시·초기화·일방통행 404·영역 밖 422·지연 응답 취소를 재검증했다. 약 83.658113m 경로가 기존과 동일했고 검증용 서버는 종료했다.

## 측정 방법

Java 21.0.12.1, 최대 힙 512MiB의 단일 JVM에서 실행했다.
실제 작은 영역 그래프와, 일방통행 및 금지 회전이 있는 고정 시드 합성 격자 3종을 사용했다.

- 데이터셋당 고정 좌표 쌍 20개를 반복한다. 경로 없음도 입력에 포함될 수 있다.
- 각 구현은 측정 전 60회 예열한다. 측정 횟수는 아래 표에 기재한다.
- 구현별 측정 순서는 데이터셋마다 번갈아 배치한다.
- 시간은 API·네트워크를 제외한 좌표 탐색 호출 전체의 `System.nanoTime` 차이다.
- 할당량은 HotSpot `ThreadMXBean.getThreadAllocatedBytes`로 측정한 호출 스레드의 누적 할당량 차이다.
  GC 후 유지 메모리나 프로세스 RSS가 아니다.
- 각 데이터셋의 20개 입력을 사전에 양쪽 구현으로 대조하고 측정 결과 checksum도 출력한다.

## 로컬 측정 결과

| 데이터 | 노드 / 간선 | 횟수/구현 | 기존 p50 → 개선 p50 | 기존 p95 → 개선 p95 | 기존 할당 bytes/요청 → 개선 |
| --- | --- | ---: | --- | --- | --- |
| 실제 작은 영역 | 79 / 103 | 200 | 0.0605 → 0.0106ms | 0.1358 → 0.0198ms | 47,852 → 5,038 |
| 격자 10×10 | 100 / 275 | 150 | 0.1168 → 0.0258ms | 0.2715 → 0.0539ms | 111,824 → 9,056 |
| 격자 50×50 | 2,500 / 7,375 | 80 | 1.9630 → 0.9057ms | 2.3981 → 1.1380ms | 2,771,999 → 208,258 |
| 격자 100×100 | 10,000 / 29,625 | 40 | 7.3216 → 2.6472ms | 9.9263 → 5.1453ms | 10,955,494 → 708,773 |

마지막 데이터셋 기준 요청당 할당량은 약 93.5%, p50 시간은 약 63.8% 감소했다.
이 데이터셋에서 12E 배열 본체는 355,500 bytes이고, 실제 호출 할당량은 큐·결과 등을 포함해 더 크다.

구간별 간선 목록을 미리 보관하므로 공유 인덱스의 비용은 추가됐다.
같은 실행에서 1만 노드 초기화 시간은 기존 25.476ms, 개선 33.473ms였다.
초기화 시간은 예열 전 단일 기록이며 별도 성능 결론의 근거로 삼지 않는다.
원시 결과: [routing-performance.txt](routing-performance.txt).

이는 JMH 다중 fork나 운영 동시 부하 시험이 아닌 로컬 진단 측정이다.
표본 수·JIT·GC·실행 순서에 영향을 받으며 전국 데이터의 처리량을 보장하지 않는다.
공유 인덱스의 유지 메모리, GC 후 live heap, 서버 최대 RSS와 동시 요청 한도는 아직 별도 측정이 필요하다.

## 재현

프로젝트 루트에서:

```sh
./backend/gradlew -p backend test
./backend/gradlew -p backend :routing-core:benchmarkRouting \
  -Pgraph=data/processed/graph-small-area.rgraph
```

`-Pgraph`를 생략하면 실제 로컬 데이터 없이 합성 격자 3종만 측정할 수 있다.
테스트 기준 구현과 벤치마크는 `src/test`에만 위치한다.
